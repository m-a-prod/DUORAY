# Отчёты об ошибках и обновления

## Отчёты об ошибках

При первом запуске DUORAY спрашивает, можно ли отправлять отчёты об ошибках.
Без ответа «Разрешить отправку» ничего не отправляется. Решение меняется в любой
момент: **Настройки → Отчёты и обновления**. Если отчёты выключить, отчёты,
ещё не отправленные из очереди, удаляются.

**Когда отправляется автоматически** (только с согласия, одна и та же ошибка —
один раз за запуск, не больше 20 отчётов за запуск):

- приложение упало (panic) — отчёт уходит при следующем запуске;
- не удалось подключиться, туннель или xray остановились;
- не удалось установить помощник;
- не удалось обновить подписку;
- не удалось установить обновление.

**Что в отчёте:** версия DUORAY, ОС и архитектура, тип ошибки и её текст,
журнал последних действий (до 300 строк), время работы, тип рендера; настройки
маршрутизации и пинга (переключатели); тип выбранного сервера: протокол,
транспорт, безопасность, число исходящих, JSON или ссылка, правился ли он.
Плюс случайный идентификатор установки: он появляется при согласии, стирается
при отказе и не связан с HWID.

**Что не отправляется никогда:** ссылки подписок, адреса и названия серверов,
ключи, пароли, UUID, e-mail, домашняя папка. Все тексты перед отправкой проходят
через чистильщик (`crates/duoray-gui/src/diag.rs`, `sanitize`): ссылки, IPv4 и
IPv6, доменные имена, UUID и длинные токены заменяются на `<url>`, `<ip>`,
`<host>`, `<uuid>`, `<secret>`. IP-адрес отправителя сервер не сохраняет: он
используется только в памяти, для лимита 30 отчётов в час.

**«Сообщить о проблеме»** в настройках отправляет отчёт с вашим описанием.
Кнопка «Что отправится?» показывает его целиком до отправки. В ответ вы
получаете код вида `DR-7K3QX9` — передайте его в поддержку.

Отчёты хранятся 90 дней.

## Обновления

DUORAY проверяет обновления через 30 секунд после запуска и затем раз в 6 часов
(**Настройки → Проверять обновления**). Новая версия скачивается в фоне.
Устанавливается она только по нажатию «Установить» в боковой панели.

Манифест обновления подписан ключом Ed25519, публичная часть вшита в
приложение (`crates/duoray-gui/src/update.rs`). Файл используется, только если
сходятся подпись манифеста, SHA-256 и размер. Поэтому даже взломанный сервер
не может подсунуть чужую программу.

| Платформа | Как ставится |
|---|---|
| Windows x64 / x86 | тихий установщик (один запрос UAC), затем DUORAY запускается снова |
| Linux AppImage x86_64 / aarch64 | AppImage заменяет себя и перезапускается |
| macOS | скачанный и проверенный `.dmg` открывается |
| Linux через `install.sh`, сборка из исходников | только сообщение о новой версии |

## Для разработчиков

Сервер — `server/duoray-hub/`: Python без зависимостей + SQLite, systemd-юнит
с `DynamicUser`. Он работает за haproxy на `duoray.dualizm.space`.

Приложение пробует хабы по очереди: `duoray.dualizm.space`, затем зеркала
`duoray.pro` (работает, тот же сервер) и `duoray.it-dualizm.space`. Ответивший хаб запоминается до
конца запуска. Чтобы включить зеркало, хватит настройки на сервере:

- A-запись домена на хаб;
- сертификат (`certbot certonly --standalone --http-01-port 8080 -d <домен>`)
  и его PEM в `bind` haproxy;
- имя в `acl host_duoray`.

Обновлять приложение для этого не нужно.

```sh
ssh "$DUORAY_HUB_SSH" duoray-reports list            # последние отчёты
ssh "$DUORAY_HUB_SSH" duoray-reports show DR-7K3QX9  # отчёт с журналом
ssh "$DUORAY_HUB_SSH" duoray-reports stats           # частые ошибки
```

Релиз всех платформ собирается в GitHub Actions (`.github/workflows/release.yml`):

1. Поднимите версию в `Cargo.toml` и закоммитьте.
2. `git tag v<версия> && git push --tags`. Actions соберёт Windows, Linux
   (AppImage, rpm, deb, tar.gz) и macOS и выложит их в GitHub Release.
3. Опубликуйте на хабе: `git checkout v<версия> && packaging/release.sh --from-github v<версия> "Что нового"`.
4. Репозиторий pacman (`https://duoray.dualizm.space/arch/$arch`) `release.sh`
   обновляет сам: он вызывает `packaging/linux/arch-repo.sh`, если в релизе есть
   пакеты Arch. Пакеты подписаны ключом `13F077054DB026DC11D58144254C5F497BDAC7B9`,
   брелок лежит в `~/.config/duoray-release/gnupg`.
5. AUR (когда будет аккаунт): `packaging/aur/update.sh --push`.

Без CI `packaging/release.sh "Что нового"` собирает здесь то, что может:
Windows, Linux x86_64. Дальше скрипт:

- собирает Windows и AppImage;
- берёт из `dist/` сборки этой версии, сделанные на других машинах (macOS, aarch64);
- подписывает манифест ключом `~/.config/duoray-release/update-signing.pem` (адрес хаба для выкладки — `DUORAY_HUB_SSH` в `~/.config/duoray-release/env`);
- выкладывает всё на хаб, манифест последним.

Ключ нельзя терять и нельзя никуда выкладывать: без него обновления не выпустить,
а с чужим ключом их не примет ни одна установленная копия.
